I'm Keshav, a software engineer at jpteam / C1X Inc. I build systems and investigate the engineering problems underneath them — the silent failure behind an HTTP 200, the keyspace mismatch behind an idle queue, the read path that should never have been computing anything.

## Professional focus

Production backends in a multi-product organisation spanning FinTech compliance, Document AI, enterprise conversational AI and high-concurrency dynamic media platforms. Most of that work is a [GST compliance and Document AI platform](/projects/fintax), where I was a primary contributor across the core domain service and the document extraction worker: ledgers with correct tax math, IMS reconciliation with the GST portal, GSTR-1 and GSTR-3B filing, a document-AI extraction pipeline, durable real-time notifications, and tenant isolation.

## Systems interests

The parts of a system that decide whether it is correct under load and under failure: concurrency control (Redis locks around redemption and OTP verification), async pipelines and their contracts (BullMQ keyspaces, domain events), read models, and the security boundary between tenants.

## AI infrastructure

The engineering around models rather than the models themselves: classification guards in front of expensive OCR, retrieval that is decided rather than automatic ([BARA](/projects/bara)), explanation built into detection ([ACFS](/projects/acfs)), and review automation that is structurally unable to change the code it reviews ([Antigravity](/projects/antigravity-pr-reviewer)).
